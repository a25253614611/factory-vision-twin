# FlowTwin｜跨鏡頭在製品追蹤數位孿生模擬器

以雙相機產線為情境的**可互動面試作品**。用 12 件合成工件、相機 A／B 的獨立軌跡、外觀特徵與通行時間，展示身分關聯、誤報覆核、遮擋和光線變化時的取捨。所有情境可重現，且不用 API key、LLM 或雲端服務。

> **誠實界線：**目前是「數位孿生概念模擬器」，不是與真實 PLC／MES／相機同步的工廠數位孿生。沒有執行影像偵測、ByteTrack 或 ReID 神經網路推論。特徵向量與延遲都是合成值；頁面指標不得當成實際產線成效。

每天只有 2 小時可學習時，依照 [四週實作課](COURSE.md)逐步從本 demo 走向真實影像 PoC 與二面準備。

## 3 分鐘啟動

需要 Python 3.10+；無第三方套件。於本資料夾執行：

```powershell
py -3 simulate.py
py -3 -m http.server 8766 --bind 127.0.0.1
```

打開 <http://127.0.0.1:8766/>。若電腦沒有 `py` 指令，改用 `python`。可按「播放產線」，切換「標準／光線／遮擋／綜合」與兩種關聯策略。靜態頁面會讀取版本庫已附的 `demo_data.json`，因此在沒有 Python 的靜態網站服務上也能展示。用 `py -3 -m unittest -v` 驗證邏輯。

## 實際做了什麼

```text
固定種子合成 WIP + A/B 相機觀測
               ↓
6–10 秒通行時間窗 → 一對一跨鏡頭關聯
               ↓
原始歐氏距離  vs  正規化餘弦相似度 + 信心門檻
               ↓
合成真值離線評估 → 互動產線與 BD/PoC 看板
```

- `simulate.py` 產生四種情境與指標，使用標準函式庫。
- `match_observations()` 只讀時間、信心、特徵和局部軌跡 ID；**不讀合成真值**。真值僅於 `evaluate()` 計分。
- `app.js` 播放工件與相機觀測，呈現跨鏡頭關聯證據、策略比較和 PoC 對話卡。
- `test_simulate.py` 驗證重現性、時間窗、一對一約束、真值隔離、光線和遮擋的取捨。

## 指標定義與限制

| 指標 | 在本模擬中的定義 | 現場 PoC 應改如何量測 |
| --- | --- | --- |
| 正確跨鏡頭關聯率 | 正確 A→B 身分連結 / 12 件投入工件 | 與人工標註雙鏡頭軌跡比對，按工件型號、班別與光線分層 |
| 錯誤關聯 | A→B 連到另一件工件 | 單獨追蹤高代價誤配，不只看整體準確率 |
| 誤報進入覆核 | 低信心合成雜訊通過信心門檻的數量 | 每班人工佇列的誤報件數和處理分鐘 |
| 人工覆核估計 | 12 − 正確關聯 + 誤報佇列 | 實測覆核工時、追溯工時和作業接受度 |
| P95 處理延遲 | 以固定公式產生的情境假設值 | 在目標邊緣設備上量測端到端輸入至看板時間 |

目前關聯只用簡化的貪婪一對一匹配，沒有相機標定、軌跡拓撲、持續時間、特徵漂移校準、軌跡裂解、模型置信校準或資料庫。測試資料很小，**不具統計代表性**。光線情境以特徵向量縮放代替真實像素光照變化；這是為了展示原始距離與正規化相似度的差別，不代表神經網路在真實光線下的表現。

## 90 秒面試展示

1. **問題（15 秒）：**「同一件在製品經過兩個相機，局部軌跡 ID 會重置。若接錯身分，後段追溯會失真。」
2. **操作（30 秒）：**選「光線突變」，展示原始外觀距離的失效，再切到正規化外觀＋通行時間窗＋信心門檻。指出 1 件低信心真實工件仍需人工覆核。
3. **商務取捨（25 秒）：**同時看正確關聯、誤報佇列、人工覆核與 P95 延遲；強調延遲數字是模擬假設。詢問客戶錯配、漏追與節拍各自的成本。
4. **落地路線（20 秒）：**以授權的雙鏡頭影片建立標註集，離線回放→邊緣設備影子運行→現場驗收。接入 PLC/MES 前，先驗證資料權限、時間同步與維護流程。

## 真實 PoC 路線

**第 1 階段，需求訪談：**確定 WIP 類型、相機位置、節拍、光線／遮擋分布，以及錯配和漏追的業務損失。問清楚資料保存、隱私和導入限制。

**第 2 階段，離線驗證：**取得已授權的同步雙鏡頭影片與人工標註軌跡。選用偵測／單鏡頭追蹤／ReID 模組，量測錯誤關聯率、召回率、每班誤報、分層表現。這時才能設定有根據的驗收門檻。

**第 3 階段，影子運行：**在目標邊緣設備上測端到端 P95 延遲、節拍、斷線恢復和人工覆核流程；不自動改動產線控制。

**第 4 階段，擴線決策：**將改善的追溯工時、覆核分鐘與系統成本相較；只有在 KPI 和 ROI 符合客戶要求時才擴大部署。

參考方向：[Delta Electronics 產業自動化與數位孿生展示](https://www.deltaww.com/en-US/solutions/electronics-assembly)、[Delta 機器視覺方案](https://www.deltaww.com/en-US/products/Machine-Vision)、[ByteTrack](https://github.com/FoundationVision/ByteTrack)、[OpenCV](https://github.com/opencv/opencv)。本作品沒有複製上述專案的程式碼或宣稱與 Delta 產品相容。

## 低 token／低成本設計

- 模擬、關聯、計分完全是本地決定性程式，**執行時 API 與模型 token 用量為 0**。
- 若將來加入文字型 Agent，先以事件摘要與固定規則篩選例外，只把必要欄位送往模型；以實際計量資料比較成本，不能引用未驗證的節省百分比。
- 儀表板使用靜態檔案，無資料庫、前端框架或大型數位孿生平台依賴。
